# 小米 14 显示与性能验证

2026-10-25，iOS 16.7.16 / Darwin 22；r54 为可恢复旧基线，r56 为八核全屏版本。

## 已验证变化

- 逻辑画布由居中的 1125×2436 改为原生 1200×2670，使用现有 4800 字节行跨度的
  启动 framebuffer。触控归一化采用同一画布，用户确认铺满屏幕且触点准确。
- CPU 全部八核已在线，先通过 r55 不挂载系统卷的独立预检，再在 r56 运行 iOS。
- 软件呈现使用绝对时间点，避免每次复制耗时累积到下次等待；跳过已错过的时间点，
  不连续补发旧帧。删除逐帧临时堆分配，增加窗口呈现计数、复制耗时和错过的定时点计数。
- 用户在设置列表持续滚动后确认，相对 r54 流畅度改善明显。

`sweetfb_hz=60` 是软件定时器上限。它不表示已测得 60 FPS，也不证明面板刷新率。
当前无 GPU 加速。最后保留的日志窗口中最长单次呈现约 2.783 ms、错过定时点为 0；
冻结末段没有新的帧提交，不能据此推算活跃滚动帧率。

## 关于本机冻结

r56 用户打开“设置 → 通用 → 关于本机”后，整块可见界面不响应，包括底部上滑。
此时内核仍完成 48 次采样并自动回到 OrangeFox，八核仍在线；触控报告 stage=5/error=0。
旧计数只有在 HID 调用返回后才增加，因此这些值尚不足以证明输入线程仍在运行。
保留日志没有采样 Preferences，不能确定设置页面究竟阻塞在哪个服务。

r57 只增加诊断：采样 Preferences、SpringBoard、backboardd 的用户调用栈；
记录触控轮询次数、缓存 IRQ 状态、工作阶段以及 HID 调用进入/返回次数。
采样器不增加硬件寄存器读取，也不改变触点协议。复现结果如下。

r57 复现结果：触控轮询次数在 20 秒内由 19651 增至 21473，HID 调用进入/返回均为 509。
Preferences 主线程卡在 `PSGAboutDataSource::_macAddress` →
`SCNetworkInterfaceCopyAllWithPreferences` → `dispatch_once_wait`；执行初始化的线程
停在 `__wait_for_IOKit_to_quiesce` → `SCDynamicStoreNotifyWait`。
因此没有证据说明八核内核或触控工作线程冻结。
Apple configd 的 InterfaceNamer 有默认 300 秒栈等待及可配置超时；尚未修改手机配置。

## 最近任务手势

r58 参考同版本 ios-sweet 的 0070/0071：接入现有原生 `pid_hibernate`（无 freezer 时
保留原实现的空操作语义），并对起始于物理屏幕边缘 48 像素内的触点设置
`kIOHIDDigitizerEventFromEdgeTip`。标记持续到抬起，后续新触点重新判定，不随移动位置改变。
屏幕阈值按本机 1200×2670 改写，没有使用参考机尺寸。
用户确认最近任务卡片已可用，“关于本机”仍在等待。此修正尚未完成全面手势验证。
