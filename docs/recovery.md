# 本地恢复与产物管理

## 恢复边界

houji 开发配置使用原生 UFS 系统卷，曾对 userdata 和 recovery 做过修改。仓库不提供通用分区表，也不包含个人设备的恢复材料。解锁 Bootloader 不代表任意分区都可以安全重写。

必须在本地保存设备匹配的 GPT、引导链、恢复镜像、校准和通信相关分区备份，另备匹配的原厂固件。恢复前核对设备、分区布局、槽位、镜像长度与哈希。不要把其他手机的校准、通信分区或 GPT 当作恢复文件。

iOS 系统卷写入后，OrangeFox 提示无法挂载 data 不等于应格式化。回恢复环境时避免误选 Android 或格式化操作，以免覆盖当前开发卷。

## 镜像保留策略

本地只保留少量匹配用途的产物：当前可启动版本、关键输入/桌面修复版本、一个已校验的回退系统卷，以及仍被构建工具使用的基础输入。早期 GPU 检查点可以保留源码、校验和及小型 EFI 产物，不必保留每轮完整镜像。

旧里程碑的 boot/EFI 文件不一定能搭配当前系统卷启动。恢复需要匹配的组件集合，不能把“曾经成功”当作跨版本兼容保证。

清理前应先生成精确清单并验证保留文件；先卸载检查用镜像，再清理过期镜像、增量包和旧缓存。分区备份和源码不应放进自动清理范围。APFS 克隆文件的逻辑容量会重复计算共享块，实际释放量以清理前后磁盘可用空间为准。

## 日志

内核检查点和用户空间采样使用独立的日志区域及校验信息；自动返回 OrangeFox 后读取。有效日志应匹配本轮 UUID 和校验值，避免误读上一轮内容。最后一次已保存检查点不一定包含导致硬复位的最后一条指令。

历史提取器和写入边界的实现保存在 `archive/scripts` 与 `kernel/overlay/iokit/Kernel/houji-ufs-root/`。历史脚本带有原实验的分区和文件校验绑定，不提供无需复核即可运行的通用刷写命令。
